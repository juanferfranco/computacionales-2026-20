## Propósito

En esta unidad usarás un triángulo en OpenGL moderno para comprender cómo una
aplicación produce una imagen. Seguiremos el recorrido de los datos desde C++
hasta la GPU: creación del contexto, carga de funciones, configuración de
vértices, ejecución de shaders y presentación del resultado. Al terminar,
deberías poder explicar por qué aparece una imagen y diagnosticar qué parte
del recorrido revisarías si no aparece o se ve distinta de lo esperado.

## Actividades

En las dos primeras sesiones analizaremos juntos un ejemplo funcional. En la

individual y sin materiales de consulta, según las condiciones del curso.

### Actividad 02: del programa al primer píxel

Construiremos en el tablero un mapa de las piezas que permiten que funcione
la aplicación:

1. **GLFW** crea la ventana y el contexto OpenGL y recibe eventos.
2. **`opengl32.lib`** participa en el enlace de la API de OpenGL disponible
   directamente en Windows.
3. **GLAD** carga, con un contexto activo, las funciones modernas que expone
   el controlador gráfico.
4. **El controlador de la GPU** implementa las operaciones gráficas que usa la
   aplicación.
5. **GLM**, cuando el programa la utiliza, aporta operaciones matemáticas con
   vectores y matrices; no crea el contexto ni dibuja por sí sola.

Seguiremos el orden de inicialización en el ejemplo y distinguiremos lo que
se necesita al compilar, enlazar y ejecutar. El profesor mostrará cómo se
relacionan las cabeceras, los archivos fuente, las bibliotecas y las DLL del
proyecto. La configuración detallada de Visual Studio será una referencia
para quien necesite resolver un problema de entorno, no una tarea de
instalación para todos.

**Pregunta de comprobación:** si la ventana se crea pero una función moderna
de OpenGL no está disponible, ¿qué parte de la secuencia revisarías y por qué?

### Actividad 04: datos de vértices y shaders

Seguiremos un dato concreto: una coordenada del arreglo de C++ hasta la
posición que recibe el vertex shader. En el tablero relacionaremos el arreglo,
el VBO, la configuración de atributos guardada por el VAO, la ubicación
`layout(location = ...)` del shader y la llamada de dibujo. Después seguiremos el
resultado hasta el fragment shader y el color que aparece en pantalla.

Haremos pequeñas predicciones antes de probar cambios en el ejemplo: alterar
una coordenada, cambiar el color que escribe el fragment shader y modificar
una ubicación de atributo. En cada caso explicaremos qué parte del recorrido
se modificó y cuál quedó igual.

**Preguntas para discutir:** ¿qué contiene el VBO y qué configuración recuerda
el VAO?, ¿por qué el shader debe recibir los datos en la ubicación esperada?,
¿qué diferencia hay entre el trabajo del vertex shader y el del fragment
shader?

### Actividad 05: interacción mediante uniforms

En esta actividad observarás cómo el mouse cambia la posición y el color del
triángulo. **No tienes que construir la aplicación desde cero.** Abre el
proyecto del triángulo simple ya configurado, reemplaza **todo el contenido de
`triangle.cpp`** por el siguiente archivo, compila y ejecuta. Los dos shaders
están incluidos como cadenas dentro del mismo archivo: no necesitas crear
otros archivos ni cambiar la configuración del proyecto. La configuración
proporcionada enlaza `glfw3.lib` de forma estática; no necesitas copiar
`glfw3.dll` junto al ejecutable.

```cpp
#include <iostream>
#include <glad/glad.h>
#include <GLFW/glfw3.h>

const unsigned int SCR_WIDTH = 400;
const unsigned int SCR_HEIGHT = 400;

unsigned int VAO = 0, VBO = 0, shaderProg = 0;

const char* vertexShaderSrc = R"glsl(
    #version 460 core
    layout(location = 0) in vec3 aPos;
    uniform vec2 offset;

    void main() {
        gl_Position = vec4(aPos.xy + offset, aPos.z, 1.0);
    }
)glsl";

const char* fragmentShaderSrc = R"glsl(
    #version 460 core
    out vec4 FragColor;
    uniform vec4 ourColor;

    void main() {
        FragColor = ourColor;
    }
)glsl";

void framebuffer_size_callback(GLFWwindow*, int width, int height) {
    glViewport(0, 0, width, height);
}

void processInput(GLFWwindow* window) {
    if (glfwGetKey(window, GLFW_KEY_ESCAPE) == GLFW_PRESS) {
        glfwSetWindowShouldClose(window, true);
    }
}

float clamp01(float value) {
    if (value < 0.0f) return 0.0f;
    if (value > 1.0f) return 1.0f;
    return value;
}

unsigned int buildShaderProgram() {
    int success = 0;
    char log[512];

    unsigned int vs = glCreateShader(GL_VERTEX_SHADER);
    glShaderSource(vs, 1, &vertexShaderSrc, nullptr);
    glCompileShader(vs);
    glGetShaderiv(vs, GL_COMPILE_STATUS, &success);
    if (!success) {
        glGetShaderInfoLog(vs, 512, nullptr, log);
        std::cerr << "ERROR VERTEX SHADER:\n" << log << '\n';
        glDeleteShader(vs);
        return 0;
    }

    unsigned int fs = glCreateShader(GL_FRAGMENT_SHADER);
    glShaderSource(fs, 1, &fragmentShaderSrc, nullptr);
    glCompileShader(fs);
    glGetShaderiv(fs, GL_COMPILE_STATUS, &success);
    if (!success) {
        glGetShaderInfoLog(fs, 512, nullptr, log);
        std::cerr << "ERROR FRAGMENT SHADER:\n" << log << '\n';
        glDeleteShader(vs);
        glDeleteShader(fs);
        return 0;
    }

    unsigned int program = glCreateProgram();
    glAttachShader(program, vs);
    glAttachShader(program, fs);
    glLinkProgram(program);
    glGetProgramiv(program, GL_LINK_STATUS, &success);
    glDeleteShader(vs);
    glDeleteShader(fs);
    if (!success) {
        glGetProgramInfoLog(program, 512, nullptr, log);
        std::cerr << "ERROR LINKING PROGRAM:\n" << log << '\n';
        glDeleteProgram(program);
        return 0;
    }
    return program;
}

void setupTriangle() {
    const float vertices[] = {
        -0.5f, -0.5f, 0.0f,
         0.5f, -0.5f, 0.0f,
         0.0f,  0.5f, 0.0f
    };

    glGenVertexArrays(1, &VAO);
    glGenBuffers(1, &VBO);
    glBindVertexArray(VAO);
    glBindBuffer(GL_ARRAY_BUFFER, VBO);
    glBufferData(GL_ARRAY_BUFFER, sizeof(vertices), vertices, GL_STATIC_DRAW);
    glVertexAttribPointer(0, 3, GL_FLOAT, GL_FALSE,
                          3 * sizeof(float), (void*)0);
    glEnableVertexAttribArray(0);
    glBindVertexArray(0);
}

int main() {
    if (!glfwInit()) {
        std::cerr << "Fallo al inicializar GLFW\n";
        return -1;
    }
    glfwWindowHint(GLFW_CONTEXT_VERSION_MAJOR, 4);
    glfwWindowHint(GLFW_CONTEXT_VERSION_MINOR, 6);
    glfwWindowHint(GLFW_OPENGL_PROFILE, GLFW_OPENGL_CORE_PROFILE);

    GLFWwindow* mainWindow = glfwCreateWindow(
        SCR_WIDTH, SCR_HEIGHT, "Triangulo interactivo", nullptr, nullptr);
    if (!mainWindow) {
        std::cerr << "No se pudo crear la ventana OpenGL 4.6\n";
        glfwTerminate();
        return -1;
    }

    glfwMakeContextCurrent(mainWindow);
    glfwSetFramebufferSizeCallback(mainWindow, framebuffer_size_callback);
    if (!gladLoadGLLoader((GLADloadproc)glfwGetProcAddress)) {
        std::cerr << "Fallo al cargar GLAD\n";
        glfwDestroyWindow(mainWindow);
        glfwTerminate();
        return -1;
    }

    int bufferWidth = 0, bufferHeight = 0;
    glfwGetFramebufferSize(mainWindow, &bufferWidth, &bufferHeight);
    glViewport(0, 0, bufferWidth, bufferHeight);
    glfwSwapInterval(1);

    shaderProg = buildShaderProgram();
    if (shaderProg == 0) {
        glfwDestroyWindow(mainWindow);
        glfwTerminate();
        return -1;
    }
    setupTriangle();

    const int offsetLocation = glGetUniformLocation(shaderProg, "offset");
    const int colorLocation = glGetUniformLocation(shaderProg, "ourColor");
    if (offsetLocation == -1 || colorLocation == -1) {
        std::cerr << "No se encontro un uniform del programa\n";
        glDeleteVertexArrays(1, &VAO);
        glDeleteBuffers(1, &VBO);
        glDeleteProgram(shaderProg);
        glfwDestroyWindow(mainWindow);
        glfwTerminate();
        return -1;
    }

    while (!glfwWindowShouldClose(mainWindow)) {
        glfwPollEvents();
        processInput(mainWindow);

        double mouseX = 0.0, mouseY = 0.0;
        glfwGetCursorPos(mainWindow, &mouseX, &mouseY);
        int windowWidth = 0, windowHeight = 0;
        glfwGetWindowSize(mainWindow, &windowWidth, &windowHeight);

        float x01 = 0.5f, y01 = 0.5f;
        if (windowWidth > 0 && windowHeight > 0) {
            x01 = clamp01(static_cast<float>(mouseX / windowWidth));
            y01 = clamp01(static_cast<float>(mouseY / windowHeight));
        }

        // El origen del mouse esta arriba; el eje Y de NDC apunta arriba.
        // El offset va de -0.5 a 0.5 para conservar el triangulo en pantalla.
        const float offsetX = x01 - 0.5f;
        const float offsetY = 0.5f - y01;

        glClearColor(0.2f, 0.3f, 0.3f, 1.0f);
        glClear(GL_COLOR_BUFFER_BIT);
        glUseProgram(shaderProg);
        glUniform2f(offsetLocation, offsetX, offsetY);
        glUniform4f(colorLocation, x01, y01, 1.0f - x01, 1.0f);
        glBindVertexArray(VAO);
        glDrawArrays(GL_TRIANGLES, 0, 3);
        glfwSwapBuffers(mainWindow);
    }

    glDeleteVertexArrays(1, &VAO);
    glDeleteBuffers(1, &VBO);
    glDeleteProgram(shaderProg);
    glfwDestroyWindow(mainWindow);
    glfwTerminate();
    return 0;
}
```

Mueve el mouse dentro de la ventana. Debes ver que el triángulo cambia de
posición y que todo el triángulo adopta un nuevo color. `Esc` cierra la
aplicación. Si el proyecto compila pero no abre, revisa primero los mensajes
de error: por ejemplo, el equipo podría no admitir el contexto OpenGL 4.6
que solicita este ejemplo.

**¿Qué hace el código?** Un `uniform` es un valor que C++ envía al programa de
shaders y que se mantiene constante durante una llamada de dibujo. Aquí
`offset` se usa en el vertex shader para sumar el mismo desplazamiento a los
tres vértices. `ourColor` se usa en el fragment shader para asignar un único
color a todos los fragmentos del triángulo. Los valores se actualizan después
de `glUseProgram` y antes de `glDrawArrays`. Las ubicaciones de ambos
`uniforms` se consultan una sola vez, después de enlazar el programa.

Las coordenadas del mouse comienzan en la esquina superior izquierda de la
ventana. Dividir `mouseX` y `mouseY` por el ancho y alto **actuales** produce
`x01` y `y01` entre 0 y 1. `clamp01` limita los valores si el cursor sale de
la ventana. Para el desplazamiento horizontal usamos `x01 - 0.5`; para el
vertical, `0.5 - y01`, que invierte el eje Y. Así el desplazamiento queda
entre -0.5 y 0.5 dentro del espacio de coordenadas de dispositivo
normalizadas (NDC). El color usa `x01` como componente roja, `y01` como verde
y `1 - x01` como azul.

El VBO sigue conteniendo las tres posiciones originales. Mover el mouse no
vuelve a cargar el VBO: solo cambia los `uniforms` usados en el siguiente
dibujo. Un atributo, en cambio, puede tener un valor diferente para cada
vértice; esa será una diferencia importante en la actividad 6.

**Para analizar en clase:** ubica en el archivo las líneas donde C++ lee el
mouse, normaliza sus coordenadas, activa el programa y envía cada `uniform`.
Predice qué ocurriría si comentaras `glUniform2f` y, por separado, si
comentaras `glUniform4f`. Contrasta tus predicciones con la aplicación.

**Pregunta de comprobación:** si el triángulo se mueve pero conserva su
geometría, ¿qué dato cambió, dónde se actualizó y por qué no hubo que volver
a definir todos los vértices?
